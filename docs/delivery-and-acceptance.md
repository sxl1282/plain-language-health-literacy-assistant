# 研发协同｜模块接口、阶段交付与验收

本页将研发协同落到阶段交付要求、模块字段与验收场景，便于需求对齐、联调和整改复验。

## 阶段交付

| 阶段 | 对齐内容 | 阶段交付要求 |
| --- | --- | --- |
| 需求与范围 | 用户流程、MVP 优先级、医疗风险边界。 | 明确术语解释和溯源优先，可选生成的定位及范围。 |
| 方案与接口 | 文本 / OCR 接入、检索结果、来源句、生成状态与风险提示。 | 统一字段和异常语义，使各模块可联调。 |
| 原型联调 | 文本到解释、通俗化、提问及风险提示的端到端链路。 | 原文入口明确、解释可核对，生成失败时保留规则结果。 |
| 评测整改 | 识别、检索、文本处理和生成相关 Bad Case。 | 归因到具体环节，明确修正措施及复验范围。 |
| 演示交付 | 界面、使用说明、方案文档、验收标准和剩余限制。 | 使用合成或去标识化材料演示，统一功能与边界描述。 |

## 模块接口约定

以下字段来自现有代码，用于说明联调时需要对齐的数据契约。

| 数据对象 | 关键字段 | 协同重点 |
| --- | --- | --- |
| 文本处理结果 | `status`、`input_type`、`original_text`。 | 区分成功与结构化错误。 |
| 术语条目 | `term`、`matched_text`、`explanation`、`start`、`end`。 | 统一术语、解释和字符位置，支持高亮与核对。 |
| 来源信息 | `marker`、`source` / `source_sentences`。 | 解释卡片与输入文档中的相关句子保持关联。 |
| 通俗化结果 | `patient_friendly_version`、`llama_patient_friendly_version`。 | 区分规则输出与可选生成结果。 |
| 生成及检查状态 | `llama_generation_status`、`baseline_faithfulness_check`、`llama_faithfulness_check`。 | 分别处理失败、未运行和风险提示。 |
| 就诊准备 | `questions`、`safety_notice`。 | 提问基于文档，产品边界持续可见。 |

## 验收标准

| 维度 | 代表场景 | 验收要求 |
| --- | --- | --- |
| 功能完整性 | 输入包含已知医学术语的出院摘要。 | 完成解释、原文溯源、通俗化输出与就诊准备问题展示。 |
| 信息可追溯性 | 同一术语在原文多次出现。 | 对应术语可定位，相关来源句可核对，解释列表去重。 |
| 医疗信息保留 | 原文含药物、剂量、结果或随访。 | 核对遗漏、变化与新增信息；发现疑点进入整改复验。 |
| 系统稳定性 | 可选 LLM 调用失败。 | 保留规则结果，明确生成不可用。 |
| 输入异常 | 空文本或 OCR 未提取到可读内容。 | 给出清晰提示，停止后续患者结果生成。 |
| 治理提示 | 检查发现潜在无依据扩展。 | 提示需核对的风险，保持人工复核入口。 |
| 隐私与边界 | 使用演示材料并开启可选生成。 | 提示输入限制与数据去向，遮蔽常见标识并说明局限。 |

本表记录验收标准与代表场景，供研发联调及复验对齐使用。
