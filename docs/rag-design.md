# 方案设计｜规则匹配与结构化检索驱动的 RAG

## 业务约束

术语解释需要对应原文、知识来源明确、问题容易定位。通俗化改写要在改善表达之外，控制信息遗漏、药物表述变化及无依据扩展。

据此采用「规则识别 → 结构化术语解释检索 → 生成上下文构造 → Llama 3.1 受约束改写」的方案，并保留规则 Baseline。

## 技术选型

| 方案 | 对当前任务的适配性 | 主要权衡 |
| --- | --- | --- |
| 规则替换 | 输出透明、成本较低，适合作为 Baseline。 | 对长文本的表达流畅度与语境理解有限。 |
| 直接使用 LLM 解释和改写 | 表达灵活，接入形式直观。 | 缺少明确知识上下文，容易出现无依据补充或含义变化。 |
| **规则匹配 + 结构化知识检索 + LLM** | 检索结果映射到术语解释，再用于生成。 | 需处理歧义词、重叠术语、词库覆盖与生成约束。 |
| 向量检索与重排 | 可作为处理开放式语义检索的后续方向。 | 当前实现围绕精准术语匹配展开，尚未接入这条链路。 |

本项目的 RAG 通过结构化知识检索为生成提供上下文。

## 处理链路与接口

| 环节 | 输入 | 输出 / 约束 | 代码依据 |
| --- | --- | --- | --- |
| 文本接入 | 英文摘要或 OCR 提取文本。 | 统一文本入口；空文本返回结构化错误。 | [pipeline.py](../code_samples/pipeline.py) |
| 术语识别 | 文本与选定术语库。 | 词边界、长短语优先、重叠消解，保留匹配位置。 | [simplifier.py](../code_samples/simplifier.py) |
| 知识检索 | 匹配到的术语。 | `term`、`matched_text`、`explanation`、`start`、`end`。 | [simplifier.py](../code_samples/simplifier.py) |
| 来源句关联 | 原文与术语条目。 | 原文来源句及标记，供界面核对。 | [pipeline.py](../code_samples/pipeline.py) 与 [UI 片段](../code_samples/streamlit_ui_excerpt.py) |
| 上下文构造 | 相关术语及其解释。 | 构造 Prompt 上下文；现有实现最多传入 30 个术语。 | [grounded_rewrite_excerpt.py](../code_samples/grounded_rewrite_excerpt.py) |
| 可选生成 | 原文、术语上下文、生成约束。 | Llama 3.1 通俗化改写；调用前对原文做常见标识遮蔽。 | [生成约束](../code_samples/grounded_rewrite_excerpt.py)、[privacy.py](../code_samples/privacy.py) |
| 风险检查与展示 | 原文、生成文本、生成状态。 | 检查潜在无依据表述；生成失败时保留规则输出。 | [风险检查](../code_samples/faithfulness_check_excerpt.py)、[pipeline.py](../code_samples/pipeline.py) |

## 关键生成约束

原有 Prompt 明确要求：

- 只使用原始出院摘要中的信息，不推断病因、风险或未陈述的医疗事实。
- 原文没有说明药物的开始、停止或调整时，不替原文作出这些判断。
- 保留诊断、药物、剂量、结果及随访信息，尽量保留原始顺序与含义。
- 不增加生活方式建议、通用健康教育或原文未说明的检查目的。
- 使用短段落，只输出改写内容。

术语库解释帮助模型理解专业词汇，但一般医学知识不能直接扩展为患者的具体诊疗结论。

## 可追溯性的层次

1. **知识对应：** 术语与选定知识库中的通俗解释对应。
2. **文档对应：** 每个解释能回到输入文档中的匹配词及来源句。
3. **生成核对：** 生成文本与原文比较，风险提示辅助人工复核。

页面的来源句属于输入文档溯源，其作用是帮助核对原文。

## 成本、复杂度与局限

- 基础解释不依赖 LLM，降低常规路径的运行成本与外部依赖。
- 可选生成在自然表达与额外响应成本之间提供取舍。
- 当前检索主要依赖词面匹配，不能完整解决同义表达与上下文歧义。
- 按原文顺序截取有限术语上下文，长文本的上下文选择仍有优化空间。
- 规则风险检查发现部分表述模式，生成忠实度仍需专门评测与复核。
